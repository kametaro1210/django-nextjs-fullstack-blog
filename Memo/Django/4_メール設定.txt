
==========================
Django メール設定メモ
==========================

このメモでは、accounts/email.pyで定義しているメールクラスについて説明します。

このファイルでは、Djoserのユーザー認証で使用するメールを作成します。
具体的には、アカウント本登録、登録完了、パスワード再設定の案内、
パスワード再設定完了の4種類のメールに対応しています。

メール本文はHTMLテンプレートで管理し、email.pyではテンプレートへ渡すユーザー情報や
認証用トークン、URLなどを準備します。


-----------------------------
1. メール処理に必要なライブラリ
-----------------------------

email.pyでは、主に次のライブラリを使用します。

from django.conf import settings

何をしているか:
Djangoのsettings.pyに定義した設定値を読み込んでいます。
サイト名、ドメイン名、送信元メールアドレス、DjoserのURL設定などを取得するために使用します。


from django.contrib.auth.tokens import default_token_generator

何をしているか:
ユーザーごとの認証用トークンを作成しています。

このトークンは、アカウント本登録やパスワード再設定のURLに含めます。
ユーザーに関係する情報から作成されるため、別のユーザーが同じURLを使うことを防ぎます。


from djoser import utils

何をしているか:
ユーザーの主キー（pk）を、メールのURLに埋め込める形式へ変換しています。

ユーザーIDをそのままURLに書くのではなく、Djoserが使用する形式に変換するために使います。


from templated_mail.mail import BaseEmailMessage

何をしているか:
HTMLテンプレートを使ったメールを作成するための基底クラスを読み込んでいます。

django-templated-mailが提供するクラスで、テンプレートの読み込みやメール送信の基本処理を担当します。


-----------------------------
2. EmailManagerクラス
-----------------------------

EmailManagerは、複数のメールで共通する送信設定をまとめたクラスです。

class EmailManager(BaseEmailMessage):

BaseEmailMessageを継承しているため、メールテンプレートのレンダリングや送信機能を利用できます。

このクラスでは、次の宛先や送信元を設定します。

- to: メインの送信先
- cc: CC（同時に送信内容を共有する宛先）
- bcc: BCC（他の宛先から見えない共有先）
- reply_to: 返信先
- from_email: 送信元

メールの種類ごとに同じ送信処理を書く必要がないように、共通の処理をEmailManagerへまとめています。


-----------------------------
3. EmailManager.sendメソッド
-----------------------------

def send(self, to, *args, **kwargs):

sendメソッドは、メールの宛先や送信元を設定し、メールを実際に送信する関数です。


1. メールテンプレートを読み込む

self.render()

何をしているか:
メールテンプレートとコンテキストデータを使って、送信するメール本文を準備します。

テンプレート内の{{ name }}や{{ url }}のような変数が、後から渡されるユーザー情報に置き換えられます。


2. メインの送信先を設定する

self.to = to

何をしているか:
sendメソッドに渡されたメールアドレスを、メインの送信先として設定しています。


3. CC、BCC、返信先を設定する

self.cc = kwargs.pop("cc", [])
self.bcc = kwargs.pop("bcc", [])
self.reply_to = kwargs.pop("reply_to", [])

何をしているか:
追加のキーワード引数からCC、BCC、返信先を取り出して設定しています。

指定されていない場合は、空のリストを使用します。

popを使うことで、取り出した設定がkwargsに残らないようにしています。


4. 送信元を設定する

self.from_email = kwargs.pop(
	"from_email", f"{settings.SITE_NAME} <{settings.DEFAULT_FROM_EMAIL}>"
)

何をしているか:
from_emailが指定されていれば、そのメールアドレスを送信元にします。

指定がない場合は、settings.pyのサイト名とデフォルト送信元アドレスを組み合わせます。

例えば、次のような形式になります。

My Blog <no-reply@example.com>


5. 親クラスの送信処理を呼び出す

super(BaseEmailMessage, self).send(*args, **kwargs)

何をしているか:
設定した宛先や本文を使って、親クラスのメール送信処理を実行しています。

EmailManagerでは送信に必要な設定を行い、実際のメール送信処理はテンプレートメール側の機能に任せています。


-----------------------------
4. get_context_dataメソッド
-----------------------------

各メールクラスには、get_context_dataメソッドが定義されています。

このメソッドは、メールテンプレートへ渡すデータを作成する関数です。

基本的な流れは次のとおりです。

1. 親クラスから基本のコンテキストを取得する
2. コンテキストからユーザーを取得する
3. ユーザー名やトークンを追加する
4. メール本文で使えるようにコンテキストを返す

コンテキストとは、HTMLテンプレートへ渡す辞書形式のデータです。

例えば、次のようなデータを渡します。

{
	"name": "ユーザー名",
	"uid": "ユーザーID",
	"token": "認証用トークン",
	"url": "本登録やパスワード再設定のURL",
	"site_name": "サイト名"
}

テンプレートでは、次のようにデータを使用できます。

{{ name }}
{{ url }}


-----------------------------
5. ActivationEmailクラス
-----------------------------

ActivationEmailは、ユーザー登録後に送信するアカウント本登録用メールのクラスです。

class ActivationEmail(EmailManager):

EmailManagerを継承しているため、共通のメール送信設定を利用できます。


使用するテンプレート:

accounts/activation.html

このテンプレートには、本登録を促す案内文と、本登録用URLへのリンクを記述します。


get_context_dataで設定するデータ:

- name: ユーザー名
- uid: URLに含めるユーザーID
- token: アカウント本登録用の認証トークン
- url: アカウントを有効化するためのURL
- domain: サイトのドメイン名
- site_name: サイト名

context["url"]では、settings.pyのDJOSER["ACTIVATION_URL"]を使用しています。
URLの中にuidとtokenを埋め込むことで、ユーザーがメールのリンクから本登録を完了できます。


-----------------------------
6. ConfirmationEmailクラス
-----------------------------

ConfirmationEmailは、アカウント本登録が完了した後に送信する確認メールのクラスです。

class ConfirmationEmail(EmailManager):

使用するテンプレート:

accounts/confirmation.html

get_context_dataでは、次の情報を設定します。

- name: ユーザー名
- site_name: サイト名

本登録はすでに完了しているため、新しい認証トークンや本登録用URLは作成しません。
登録が完了したことをユーザーへ知らせるためのメールです。


-----------------------------
7. ForgotPasswordEmailクラス
-----------------------------

ForgotPasswordEmailは、パスワードを忘れたユーザーへ送信するメールのクラスです。

class ForgotPasswordEmail(BaseEmailMessage):

使用するテンプレート:

accounts/forgot_password.html

get_context_dataでは、次の情報を設定します。

- name: ユーザー名
- uid: URLに含めるユーザーID
- token: パスワード再設定用の認証トークン
- url: パスワードを再設定するためのURL
- domain: サイトのドメイン名
- site_name: サイト名

settings.pyのDJOSER["PASSWORD_RESET_CONFIRM_URL"]を使用して、パスワード再設定用URLを作成します。

このURLをフロントエンドで開くことで、ユーザーは新しいパスワードを入力できます。

このクラスは、現在のemail.pyではEmailManagerではなくBaseEmailMessageを直接継承しています。
そのため、EmailManagerで追加した共通の送信設定を必ず利用する設計ではありません。


-----------------------------
8. ResetPasswordEmailクラス
-----------------------------

ResetPasswordEmailは、パスワードの変更が完了した後に送信する確認メールのクラスです。

class ResetPasswordEmail(BaseEmailMessage):

使用するテンプレート:

accounts/reset_password.html

get_context_dataでは、次の情報を設定します。

- name: ユーザー名
- site_name: サイト名

パスワード変更はすでに完了しているため、新しいuid、token、URLは作成しません。
パスワードが正常に変更されたことをユーザーへ通知するためのメールです。

このクラスもBaseEmailMessageを直接継承しているため、ForgotPasswordEmailと同じく、
EmailManagerのsendメソッドを自動的に利用する関係にはなっていません。


-----------------------------
9. 認証用URLとトークンの流れ
-----------------------------

アカウント本登録やパスワード再設定では、メール内のURLを使って本人確認を行います。

基本的な流れは次のとおりです。

1. ユーザーが登録またはパスワード再設定を要求する
2. Djangoがユーザー情報からuidとtokenを作成する
3. uidとtokenを含むURLを作成する
4. 作成したURLをメールテンプレートへ渡す
5. ユーザーがメール内のリンクを開く
6. Djoserがuidとtokenを検証する
7. 問題がなければ本登録またはパスワード再設定を実行する

tokenは認証に使用する一時的な値です。
URLを知っているだけではなく、正しいユーザーと有効なtokenが必要になるため、
第三者による不正な本登録やパスワード変更を防ぎやすくなります。


-----------------------------
10. 必要なDjango設定
-----------------------------

メール本文やURLを正しく作成するために、settings.pyには次のような設定が必要です。

- SITE_NAME: サイト名
- SITE_DOMAIN: サイトのドメイン名
- DEFAULT_FROM_EMAIL: デフォルトの送信元メールアドレス
- DJOSER["ACTIVATION_URL"]: アカウント本登録URLの形式
- DJOSER["PASSWORD_RESET_CONFIRM_URL"]: パスワード再設定URLの形式

また、メールを送信するためには、開発環境または本番環境に応じたメールバックエンドの設定も必要です。

開発中は、メールをコンソールに表示する設定にすると、実際にメールを送信せず内容を確認できます。
本番環境では、SMTPなどのメールサーバー設定を行います。


-----------------------------
11. 必要なパッケージ
-----------------------------

このメール処理では、主に次のパッケージを使用します。

- djoser: ユーザー登録やパスワード再設定などの認証API
- django-templated-mail: HTMLテンプレートを使ったメール作成
- Django: 設定値、ユーザー認証、メール送信の基本機能

requirements.txtにパッケージを記述しておくと、次のコマンドで同じ環境を作成できます。

python -m pip install -r requirements.txt


-----------------------------
12. メール送信全体の流れ
-----------------------------

メール送信時は、次のような順番で処理されます。

1. Djoserが送信するメールの種類を決定する
2. 対応するメールクラスを呼び出す
3. template_nameで指定されたHTMLテンプレートを読み込む
4. get_context_dataでユーザー名やURLを準備する
5. テンプレートへコンテキストを渡す
6. renderでメール本文を作成する
7. 宛先や送信元を設定する
8. 親クラスのsend処理でメールを送信する

このように、メール本文の見た目はHTMLテンプレートで管理し、
ユーザーごとに変わる情報はemail.pyで準備する構成になっています。


-----------------------------
13. まとめ
-----------------------------

email.pyは、Djoserの認証処理で使用するメールを作成するファイルです。

EmailManagerは、メールの宛先、CC、BCC、返信先、送信元などの共通設定を担当します。

各メールクラスは、メールの種類に応じたテンプレートとコンテキストデータを指定します。

- ActivationEmail: アカウント本登録メール
- ConfirmationEmail: アカウント本登録完了メール
- ForgotPasswordEmail: パスワード再設定案内メール
- ResetPasswordEmail: パスワード再設定完了メール

特に本登録とパスワード再設定では、uidとtokenを含むURLを作成します。
ユーザーがメール内のURLを開くことで、Djoserが本人確認を行い、認証処理を進めます。

つまりemail.pyは、
「認証処理に必要な情報をテンプレートへ渡し、ユーザーへ案内メールを送信する役割」
を持つファイルです。
