==========================
Djangoマイグレーション手順
==========================

マイグレーションとは、models.pyに書いたモデル（データベースの設計）を、
実際のデータベースへ反映する仕組みです。

例えば、ユーザーの項目を追加したり、項目の名前や種類を変更したりした場合に使用します。

以下のコマンドは、manage.pyがあるbackend-djangoフォルダで実行します。
実行前に、1_Django準備の手順で仮想環境を作成し、ライブラリをインストールしておきます。


1. マイグレーションファイルを作成する
--------------------------------------

実行するコマンド:

python manage.py makemigrations

何をしているか:
models.pyの変更を確認し、データベースへ反映するための設計書を作成します。
この設計書は、アプリのmigrationsフォルダに保存されます。

特定のアプリだけを対象にする場合:

python manage.py makemigrations accounts

今回のプロジェクトでは、ユーザー関連のモデルを変更したときに使用します。


2. マイグレーションを実行する
------------------------------

実行するコマンド:

python manage.py migrate

何をしているか:
作成されたマイグレーションファイルを読み込み、データベースにテーブルや項目を作成・変更します。

初めてプロジェクトを作成したときにも実行します。
Djangoの管理画面やユーザー機能に必要な標準テーブルも作成されます。


3. 実行された状態を確認する
----------------------------

実行するコマンド:

python manage.py showmigrations

何をしているか:
マイグレーションの一覧と、実行済みかどうかを表示します。

[X] が付いているものは実行済みです。
[ ] のものは、まだ実行されていません。

未実行のマイグレーションがあるかだけ確認する場合:

python manage.py migrate --plan


4. マイグレーションが必要なとき
--------------------------------

次のような変更をした場合は、通常マイグレーションが必要です。

- models.pyにモデルを追加した
- モデルに項目（フィールド）を追加した
- 項目の名前やデータ型を変更した
- 項目を削除した
- null、default、uniqueなどの設定を変更した

手順は次のとおりです。

1. models.pyを変更する
2. python manage.py makemigrations を実行する
3. 作成されたマイグレーションファイルを確認する
4. python manage.py migrate を実行する
5. python manage.py check で設定を確認する


5. マイグレーションが通常不要な変更
------------------------------------

次の変更だけであれば、通常はマイグレーション不要です。

- views.pyの処理を変更した
- urls.pyのURLを変更した
- serializers.pyの処理を変更した
- admin.pyの表示方法を変更した
- settings.pyの表示言語やJWT設定を変更した
- HTMLやCSSを変更した

ただし、モデルに関係する設定を変更した場合は、マイグレーションが必要になることがあります。


6. 初回マイグレーションの流れ
------------------------------

マイグレーションファイルを作成します。

python manage.py makemigrations

データベースへ反映します。

python manage.py migrate


7. マイグレーションを取り消す場合
----------------------------------

例えばaccountsアプリを、最初の状態まで戻す場合:

python manage.py migrate accounts zero

特定の番号まで戻す場合:

python manage.py migrate accounts 0001

ただし、マイグレーションを戻すとテーブルや項目が削除され、データが失われる場合があります。
本番環境や大切なデータがある場合は、実行前に必ずバックアップを作成します。


覚えておくポイント
--------------------

makemigrations:
models.pyの変更から、データベース変更用の設計書を作成する。

migrate:
設計書の内容を、実際のデータベースへ反映する。

モデルを変更したら、次の2つをセットで実行します。

python manage.py makemigrations
python manage.py migrate
