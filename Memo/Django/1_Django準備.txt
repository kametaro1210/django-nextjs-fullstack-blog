==========================
Djangoプロジェクト準備メモ
==========================

このメモでは、Djangoを使い始めるまでの準備と、プロジェクト・アプリケーションを作成する手順を説明します。

基本的に、以下のコマンドはPowerShellで実行します。
また、特に記載がない限り、Django用のフォルダ（backend-django）に移動してから実行します。

-----------------------------
1. Django用フォルダへ移動する
-----------------------------

実行するコマンド:

cd backend-django

何をしているか:
現在いる場所を、Djangoのバックエンド用フォルダへ移動しています。

なぜ必要か:
仮想環境の作成やDjangoプロジェクトの作成を、決めたフォルダ内で行うためです。
コマンドを実行する場所が違うと、ファイルが意図しない場所に作成されることがあります。

-----------------------------
2. .gitignoreを作成する
-----------------------------

実行するコマンド:

New-Item .gitignore -ItemType File

何をしているか:
Gitで管理しないファイルやフォルダを指定するための、.gitignoreファイルを作成しています。

その後、.gitignoreに次のような内容を書きます:

myvenv
db.sqlite3
.vscode
__pycache__
*.pyc
.env

なぜ作成するか:
Gitは、ソースコードの変更履歴を管理するためのツールです。
しかし、仮想環境、データベース、パスワードなどの秘密情報、Pythonが自動生成するキャッシュは、
Gitで共有する必要がありません。

.gitignoreに書いたファイルやフォルダは、Gitの管理対象から除外されます。
特に.envにはパスワードやAPIキーを書くことがあるため、GitHubなどへ公開しないことが重要です。

すでに.gitignoreがある場合は、同じファイルをもう一度作成する必要はありません。

-----------------------------
3. 仮想環境を作成する
-----------------------------

実行するコマンド:

python -m venv myvenv

何をしているか:
myvenvという名前のPython仮想環境を作成しています。

なぜ必要か:
仮想環境を使うと、このDjangoプロジェクト専用のライブラリを用意できます。
他のプロジェクトのライブラリと混ざらないため、プロジェクトごとに違うバージョンを使えます。

myvenvは一度作成すれば、通常は毎回作成する必要はありません。

--------------------------------
4. 仮想環境に入る（有効化する）
--------------------------------

PowerShellで実行するコマンド:

.\myvenv\Scripts\Activate.ps1

何をしているか:
作成した仮想環境を有効にしています。

有効になると、PowerShellの行頭に次のように表示されます:

(myvenv)

この表示がある間にインストールしたPythonライブラリは、myvenvの中に入ります。

もしスクリプト実行ポリシーのエラーが出た場合は、PowerShellを管理者として実行せず、
まずVS Codeのターミナルを開き直して確認します。環境によっては実行ポリシーの変更が必要です。

------------------------------------------------------
5. requirements.txtからライブラリをインストールする
------------------------------------------------------

仮想環境を有効にした状態で実行するコマンド:

python -m pip install -r requirements.txt

何をしているか:
requirements.txtに書かれたライブラリをまとめてインストールしています。
ライブラリ名やバージョンはrequirements.txtで管理するため、ここでは個別の名前を指定しません。

なぜこの書き方をするか:
python -m pipと書くと、現在使用しているPython（通常は有効化した仮想環境のPython）に対応するpipを実行できます。
pip.exeを直接実行できないWindows環境でも使いやすい方法です。

----------------------------------
6. 仮想環境から出る（無効化する）
----------------------------------

実行するコマンド:

deactivate

何をしているか:
現在の仮想環境を終了し、通常のPython環境に戻しています。

行頭の(myvenv)という表示が消えれば、仮想環境から出た状態です。

--------------------------------
7. Djangoプロジェクトを作成する
--------------------------------

backend-djangoフォルダで、仮想環境を有効にした状態で実行します。

実行するコマンド:

django-admin startproject mysite .

何をしているか:
Djangoプロジェクトの基本ファイルを作成しています。
mysiteはプロジェクトの名前です。
最後のドット（.）は、現在いるbackend-djangoフォルダ内に作成する、という意味です。

主に次のものが作成されます:

manage.py
mysite/

manage.pyは、サーバー起動やアプリ作成など、Djangoの操作に使う管理用ファイルです。
mysiteフォルダには、設定ファイルやURL設定など、プロジェクト全体の設定が入ります。

プロジェクトとは:
WebサイトやWeb API全体の設定をまとめた単位です。
データベース設定、URL設定、使用するアプリケーションなどを管理します。

------------------------------------
8. Djangoアプリケーションを作成する
------------------------------------

manage.pyがあるbackend-djangoフォルダで実行します。

実行するコマンド:

python manage.py startapp accounts

何をしているか:
accountsという名前のDjangoアプリケーションを作成しています。

アプリケーションとは:
プロジェクト内の一つの機能を担当する部品です。
例えば、ユーザー機能、ブログ記事、コメント機能などを、それぞれ別のアプリケーションとして分けられます。

このコマンドを実行すると、accountsフォルダ内にmodels.py、views.py、admin.pyなどが作成されます。

プロジェクトがWebサイト全体だとすると、アプリケーションはその中の機能ごとの部品です。

----------------
9. 作成後の確認
----------------

manage.pyがあるフォルダで、仮想環境を有効にして実行します。

python manage.py check

エラーが表示されなければ、Djangoの設定に大きな問題がないことを確認できます。

開発用サーバーを起動する場合は、次のコマンドを実行します:

python manage.py runserver

ブラウザで http://127.0.0.1:8000/ を開くと、Djangoの画面を確認できます。
サーバーを停止するには、ターミナルでCtrl+Cを押します。

----------------------
全体の流れ（まとめ）
----------------------

cd backend-django
python -m venv myvenv
.\myvenv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
django-admin startproject mysite .
python manage.py startapp accounts
python manage.py check

作業を終えるとき:

deactivate
